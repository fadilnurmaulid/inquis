# Pedagogical Specification

## Purpose

This document defines how educational interactions inside INQUIS should be translated into concrete application behavior.

It complements:

* `steering/product-vision.md`
* `steering/lidm-2026.md`
* `steering/learning-framework.md`

This document does not redefine the learning philosophy established in those files. Instead, it specifies how that philosophy is implemented throughout the product.

---

# Scope

This specification governs:

* learning activity design
* interaction sequencing
* feedback strategy
* scaffolding
* progression
* assessment behavior
* teacher support
* student autonomy

It applies to every learning world and future expansion.

---

# Pedagogical Principles

## Inquiry Before Explanation

Students should first investigate a phenomenon before receiving formal explanations.

The system should encourage:

* observing
* comparing
* questioning
* predicting
* testing
* concluding

Direct instruction should only appear after meaningful exploration.

---

## Learning Through Discovery

Activities should allow students to construct understanding through interaction rather than memorization.

Learning experiences should prioritize:

* experimentation
* manipulation
* exploration
* reflection

---

## Curiosity-Driven Progression

Progression should reward curiosity rather than speed.

The application should avoid:

* rushing learners
* time pressure
* excessive penalties

Instead, learners should be encouraged to retry, explore alternatives, and refine their reasoning.

---

## Mistakes as Learning Opportunities

Incorrect answers are instructional moments.

The system should:

* avoid punitive feedback
* provide constructive hints
* encourage another attempt
* reinforce scientific reasoning

Incorrect responses should never be framed as failure.

---

## Scaffolded Independence

Support should gradually decrease as learners demonstrate competence.

Typical scaffold progression:

| Stage        | System Support        |
| ------------ | --------------------- |
| Introduction | Guided exploration    |
| Practice     | Contextual hints      |
| Mastery      | Minimal guidance      |
| Reflection   | Independent reasoning |

---

## Evidence-Based Reasoning

Students should justify observations whenever appropriate.

Activities should encourage learners to answer questions such as:

* What did you notice?
* Why do you think that happened?
* What pattern do you see?
* What evidence supports your idea?

---

# Learning Session Structure

Every learning activity should generally follow this sequence.

## 1. Context

Introduce an engaging situation.

Goal:

* activate curiosity
* establish relevance

---

## 2. Exploration

Learners interact freely with objects.

System behavior:

* minimal interruption
* immediate interaction
* safe experimentation

---

## 3. Observation

Students identify similarities, differences, or changes.

The system may prompt observations without revealing answers.

---

## 4. Hypothesis

Learners make predictions before confirmation.

Predictions should be encouraged even when uncertain.

---

## 5. Experiment

Students test their predictions through interaction.

Feedback should emerge naturally from the simulation whenever possible.

---

## 6. Reflection

Students compare:

* prediction
* observation
* outcome

Reflection consolidates learning before progression.

---

# Feedback Strategy

Feedback should be:

* immediate
* specific
* encouraging
* educational

Avoid generic responses such as:

* Correct!
* Wrong!

Prefer responses that explain why an outcome occurred or prompt further investigation.

---

# Hint Strategy

Hints should be progressive.

| Hint Level | Purpose                           |
| ---------- | --------------------------------- |
| Level 1    | Redirect attention                |
| Level 2    | Highlight relevant evidence       |
| Level 3    | Suggest reasoning pathway         |
| Level 4    | Reveal solution only if necessary |

The system should reveal one hint level at a time.

---

# Motivation Strategy

Intrinsic motivation is preferred over extrinsic rewards.

The application should emphasize:

* discovery
* mastery
* progress
* curiosity

Gamification should support learning rather than replace it.

---

# Progression Rules

A learner progresses after demonstrating sufficient understanding, not merely completing interactions.

Possible indicators include:

* successful inquiry completion
* consistent reasoning
* completion of reflection prompts
* satisfactory assessment outcomes

Exact thresholds are defined within individual feature specifications.

---

# Teacher Role

Teachers act as facilitators rather than information providers.

The platform should enable teachers to:

* monitor progress
* identify misconceptions
* support struggling learners
* encourage discussion after digital activities

---

# Accessibility Considerations

Pedagogical interactions should remain accessible for diverse learners.

Design should prioritize:

* clear instructions
* simple language
* visual reinforcement
* multiple attempts
* predictable interaction patterns

---

# Cross-World Consistency

Every learning world should maintain consistent pedagogical behavior.

Common expectations include:

* inquiry-first interaction
* scaffolded support
* reflective closure
* constructive feedback
* evidence-based reasoning

World-specific mechanics may differ, but these principles remain constant.

---

# Success Indicators

Implementation should support the following educational outcomes:

* increased observation skills
* improved pattern recognition
* stronger classification ability
* better prediction skills
* development of scientific reasoning
* increased learner confidence during inquiry
